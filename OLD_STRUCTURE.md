## 3. Declared package dependency graph

Enforced by `tools/PackageCheck.java` through its `ALLOWED` text block. `config`, `glicko` and `text`
have an empty right-hand side — they import nothing from the plugin at all. `me.obvgreen` (the
composition root) is exempt from the cycle rule because every wired package names the plugin class
and the plugin class names them back.

```
me.obvgreen              -> arena, command, config, database, dialog, dialog.setup,
                           glicko, item, listener, placeholder, text
me.obvgreen.arena        -> config, database, glicko, text, me.obvgreen
me.obvgreen.command      -> arena, database, text, me.obvgreen
me.obvgreen.config       -> (leaf)
me.obvgreen.database     -> glicko
me.obvgreen.dialog       -> database, text, me.obvgreen
me.obvgreen.dialog.setup -> arena, command, dialog, text, me.obvgreen
me.obvgreen.glicko       -> (leaf)
me.obvgreen.item         -> text
me.obvgreen.listener     -> arena, item, text, me.obvgreen
me.obvgreen.placeholder  -> arena, database, dialog, me.obvgreen
me.obvgreen.text         -> (leaf)
```

Wiring order in `onEnable`: settings → glicko → database → arenas → placeholder cache → dialogs.

paperweight, no shadow. `rootProject.name = "kingoftheladder"`, `group = "me.obvgreen"`,
`version = "1.0.0"`.

**Toolchain.** `JavaLanguageVersion.of(25)` via a Gradle toolchain (so `JAVA_HOME` is irrelevant),

`org.gradle.java.installations.auto-detect=true` and `auto-download=false`, and
`-Xmx1g -Dfile.encoding=UTF-8`. Compiler args: `-Xlint:all,-serial,-processing`, encoding UTF-8.

nothing is bundled into the jar.

# 7. Tools — not part of the compiled plugin

Both live in `tools/`, are excluded from the `main` source set, and are compiled by the
`compileTools` task into `build/tools`.

### `tools/GlickoCheck.java` (7 808 B)
Standalone `main` verifying the Glicko-2 implementation against Glickman's worked example,
head-to-head symmetry and edge cases. Prints each assertion and throws with expected vs. actual on
drift. Run with `.\gradlew.bat checkGlicko`.

### `tools/PackageCheck.java` (14 546 B)
Standalone `main` guarding the package layout. Reads `src/main/java` from disk, prints each rule as
it applies it, and throws on the first failure. Run with `.\gradlew.bat checkPackages`.

Enforces four rules:
1. **Package matches path** — every file sits in the directory its `package` declaration names.
2. **No fully-qualified plugin references** — cross-package access must go through an import; comments and javadoc are ignored.
3. **Declared dependencies only** — every `me.obvgreen` → `me.obvgreen` import must appear in the `ALLOWED` text block.
4. **No cycles** — Kahn's algorithm over the package graph, with the composition root removed.

**Methods**
- `public static void main(String[] args) throws IOException` — Runs the five checks in order and reports.
- `private void parseAllowList()` — Splits the `ALLOWED` text block into `package -> dependency set`, normalising short names to `me.obvgreen.*`.
- `private void scan() throws IOException` — Walks the source tree, verifies path/package agreement, and builds the actual import graph.
- `private static String owningPackage(String typeName, Set<String> declared)` — Returns the declared package owning a type name, or null.
- `private void checkDeclaredPackagesAreRegistered()` — Fails any package absent from the allow list.
- `private void checkQualifiedReferences() throws IOException` — Line-scans code (skipping comments) for dotted `me.obvgreen.` references.
- `private void checkAllowedDependencies()` — Fails any cross-package import not in the allow list.
- `private void checkNoCycles()` — Kahn's algorithm over the package graph minus the composition root; names the stuck packages on failure.
- `private void report()` — Prints the allow list and either `ALL CHECKS PASSED` or every failure, then throws.
- `private static void pass(String message)` — Prints a `PASS` line.
- `private static String read(Path file)` — Reads a file as UTF-8, wrapping `IOException`.
- `private static String rel(Path file)` — Path relative to `SOURCE_ROOT`, with `/` separators.
- `private static Path parentOf(Path file)` — The file's parent directory.
- `private static Path directoryFor(String pkg)` — The directory a package name maps to under `SOURCE_ROOT`.

# 8. Observations from the scan

Recorded as facts from reading the code — no changes proposed.

- **The `README.md` package tree is out of date.** It states subcommands live under
  `me.obvgreen.command.sub`; all 16 command classes are in `me.obvgreen.command` directly. The
  `ALLOWED` map in `tools/PackageCheck.java` also lists only `me.obvgreen.command` — there is no
  `.sub` package anywhere in the tree.
- **`checkGlicko` is not wired into `check`.** Only `checkPackages` is attached to `check`, so
  `build` verifies the package layout but not the rating arithmetic.
- **`DatabaseManager.onlinePlayerCount()` returns `cache.size()`** — the number of players ever seen,
  not the number online. `KingOfTheLadder.onEnable()` logs this as a player count.
- **`GlickoManager.decay(...)` has no caller** in the plugin source. The inactivity growth constant is
  read from config in the constructor and stored in `inactivityGrowthPerDay`, which is only consumed
  by that method.
- **`GlickoManager.MIN_DEVIATION`, `MIN_RATING`, `MAX_RATING`, `WIN`, `LOSS`** are declared but not
  referenced by any other plugin class.
- **`SetupDialogManager` holds `plugin` and `view` fields** described in code as only passed through
  to `SetupDialogs`; `DialogManager` is a near-duplicate role held separately on the plugin class.
- **`CommandPermissions.USE`** is the interface default in `KotlSubcommand.permission()`, so
  `TopCommand` and `ListArenasCommand` inherit `kotl.use` without declaring it.
- **10 subcommands** are instantiated by `CommandRegistry`, matching the 10 non-abstract
  `KotlSubcommand` implementations in `command/`.
