**Methods — movement, knockoff and death**

With a membership name that no longer resolves: leaves. Otherwise calls `handleKnockoff` when `arena.isKnockedOff(to.getY())`, or leaves when `!arena.contains(to)`.
- `public void handleKnockoff(Player victim, Arena arena)` — heals the victim, teleports them to the arena respawn point, then delegates to `scoreKnockoff(victim, arena)`. This is the only path that moves a player in or out of a region.

- `private void scoreKnockoff(Player victim, Arena arena)` — the part of a knockoff that happens whether the victim died or merely fell: consumes the attacker attribution, increments the victim's `DEATHS`; without an attacker sends the self-knockoff message, otherwise increments the attacker's `KILLS`, calls `applyCombatRating(attacker, victim)` and sends `knockedByMessage` / `knockoffMessage` with `<player>` and `<arena>` substituted.
- `private void applyCombatRating(Player winner, Player loser)` — reads both `PlayerStats`, calls `glicko.rateMatch(ratingOf(winnerStats), ratingOf(loserStats))`, applies index 0 to the winner and index 1 to the loser via `database.applyRating`, and sends each the `ratingMessage` with `<rating>` replaced by the signed delta.
- `private static String formatSigned(double delta)` — `String.format(Locale.ROOT, "%+.1f", delta)`.
- `private static GlickoRating ratingOf(PlayerStats stats)` — builds a `GlickoRating` from the row's rating, deviation and volatility.

## `tools/GlickoCheck.java` (146 lines)

`public final class` in the default package. Verifies the Glicko-2 implementation against Mark
Glickman's own worked example, which publishes every intermediate value. Needs no test framework.

- `public static void main(String[] args)` — runs `paperExample()`, then `headToHead()`, then `edgeCases()`, printing `ALL CHECKS PASSED` at the end.
- `private static void paperExample()` — the paper's Table example verbatim: rating 1500 / RD 200 / σ 0.06 against 1400/RD 30, 1550/RD 100 and 1700/RD 300, scoring win-loss-loss with τ 0.5; asserts the three `g(φ)` values, the three `E` values, and the published `r' = 1464.06`, `RD' = 151.52`, `σ' = 0.05999`.
- `private static void headToHead()` — KotL's real call shape: one `rateMatch` between two default players, asserting the winner ends above 1500, the loser below, the exchange is zero-sum, RD tightened, symmetric RD, and that an underdog gains more than a favourite in the same matchup.
- `private static void edgeCases()` — scale round-trips at 1500 and 1900, `E = 0.5` for an even matchup, `decay` over 365 idle days clamping at RD 350 while leaving the rating alone, zero decay as a no-op, and `expectThrows` for an empty period, mismatched scores and self-play.
- `private static void expectThrows(String label, Runnable action)` — runs the action and requires an `IllegalArgumentException`, printing `ok rejects …`; throws an `AssertionError` otherwise.
- `private static double sign(double value)` — `-1.0`, `0.0` or `1.0`.
- `private static void check(String label, double actual, double expected)` — delegates with a `1e-9` tolerance.
- `private static void check(String label, double actual, double expected, double tolerance)` — throws an `AssertionError` naming the label, expected and actual when they differ by more than the tolerance; otherwise prints `ok …`.

## `tools/PackageCheck.java` (330 lines)

`public final class` in the default package. Enforces the package layout. Reads the source tree from
disk and needs nothing on the classpath.

**Rules enforced**

1. **Package matches path** — every file under `src/main/java` sits in the directory its `package` declaration names.
2. **No fully-qualified plugin references** — code must reach another class through an import, never a dotted name at the call site. Comments are ignored, so javadoc may still spell a class out in full.
3. **Declared dependencies only** — every cross-package `me.obvgreen` import must be listed in `ALLOWED`. A new package must be registered before it can be used.
4. **No cycles** — apart from the composition root, the package graph must be acyclic. Kahn's algorithm is run with the root removed, because every wired package names the plugin class and the plugin class names them back.

**Fields:** `private static final Path SOURCE_ROOT = Path.of("src", "main", "java")`;
`private static final String ROOT = "me.obvgreen"`; `private static final String ALLOWED` — the
text block reproduced in section 3; `private static final Pattern PACKAGE`, `IMPORT`, `QUALIFIED`
— the three regexes; `private final Map<String, Set<String>> allowed`; `actual`; `private final List<String> failures`.

- `public static void main(String[] args) throws IOException` — runs `parseAllowList()`, `scan()`, `checkDeclaredPackagesAreRegistered()`, `checkQualifiedReferences()`, `checkAllowedDependencies()`, `checkNoCycles()`, then `report()`.
- `private void parseAllowList()` — splits each `ALLOWED` line on `=`, trims each dependency and normalises a short name to the fully qualified form, filling `allowed`.
- `private void scan() throws IOException` — walks the source root, records a failure for any file with no `package` declaration or whose package disagrees with its directory, passes the path check, then re-reads every file to collect the owning package of each non-wildcard `me.obvgreen` import into `actual`.
- `private static String owningPackage(String typeName, Set<String> declared)` — the longest declared package that is a proper parent of `typeName` with no further dot in the remainder, or null.
- `private void checkDeclaredPackagesAreRegistered()` — reports any package in `actual` that is missing from `ALLOWED`, telling the reader to add it there.
- `private void checkQualifiedReferences() throws IOException` — line-by-line over every file, skipping block comments, `//` comments, javadoc continuation lines, `package` and `import` lines, and reports any remaining line containing `me.obvgreen.`.
- `private void checkAllowedDependencies()` — for every edge in `actual`, reports the source package "may not depend on" the target when it is not in `ALLOWED`.
- `private void checkNoCycles()` — builds the graph with the root removed, seeds in-degrees, and runs Kahn's algorithm; any node left with in-degree above zero is reported as a cycle.
- `private void report()` — prints the allow list, then either `ALL CHECKS PASSED` or every failure to stderr followed by an `IllegalStateException` naming the violation count.
- `private static void pass(String message)` — prints `PASS  …`.
- `private static String read(Path file)` — UTF-8 read, wrapped in an `IllegalStateException` on `IOException`.
- `private static String rel(Path file)` — the path relative to `SOURCE_ROOT` with forward slashes.
- `private static Path parentOf(Path file)` — the file's parent.
- `private static Path directoryFor(String pkg)` — `SOURCE_ROOT.resolve(pkg.replace('.', '/'))`.

# 8. Factual observations from the scan

Statements of fact about the code as written, not recommendations.

1. `CommandRegistry.visibleTo(CommandContext)` is declared `List<String>` (CommandRegistry.java:60) and returns an `ArrayList<String>` of subcommand names. `KotLCommand.onTabComplete` consumes it as a `List<String>`. Its name suggests subcommands rather than names.
2. `CommandRegistry.names()` (line 53) has a javadoc that says "Every registered spelling, primary names first, de-duplicated", but the body only appends each subcommand's primary `name()`; aliases are not included.
3. `DialogManager` builds its own `new DialogView(plugin)` in its constructor (field `view`), and `KingOfTheLadder` separately holds its own `dialogView` instance for `SetupDialogManager`. Two `DialogView` objects exist at runtime.
4. `DialogManager.openLeaderboards` is reached only from `TopCommand`. The plugin reaches it through the `dialogs` field and its `dialogManager()` accessor; `KingOfTheLadder.dialogs` itself is never otherwise read.
5. `DatabaseManager.top(...)` always builds `RankEntry` with `position = 0`. The 1-based position is applied afterwards by `PlaceholderCache.refreshNow()`, which rebuilds each entry.
6. `DatabaseManager.onlinePlayerCount()` returns `cache.size()`, the number of cached rows, not `Bukkit.getOnlinePlayers().size()`.
7. `DatabaseManager.read(ResultSet)` does not read the `last_seen` column, although `UPSERT` writes it.
8. `DialogView` and `DialogManager` both depend on `me.obvgreen.KingOfTheLadder`, so the dialog package is not a leaf despite owning most of the UI.
9. `SetupActions.run` constructs a `CommandContext` with the hard-coded label `"kotl"`, and passes `[subcommand, arguments…]` as the argument array, so `args[0]` is the subcommand name exactly as `CommandContext.arg(0)` expects.
10. `KotlSubcommand.execute` returns a `boolean`, but `KotLCommand.onCommand` ignores it and always returns `true` from the Bukkit `CommandExecutor`.
11. `ToggleCommand` is the only subcommand with `kotl.admin` that does not override `requiresPlayer()`, so `/kotl toggle <name>` accepts a console sender. `ListArenasCommand` also does not override it, but it needs no player. `SetupCommand`, `TopCommand`, `WandCommand`, `CreateCommand`, `SetPlateCommand` and `RespawnCommand` all require a player.
12. `HelpCommand` overrides `permission()` to return `null`, so `/kotl help` is reachable by anyone; every other subcommand ends up with either `kotl.use` or `kotl.admin`.
13. `GlickoManager.rate` rejects self-play by reference identity (`opponent == player`), not by value. `GlickoCheck` relies on that distinction, passing the very same instance.
14. `ArenaManager.arenas()` returns `List.copyOf(arenas.values())`, an immutable copy, on every call; it is used by the dialogs, `/kotl list` and the setup menu.
15. `SavedState.restore` reapplies `Math.min(health, maxHealthOf(player))` after resetting the `MAX_HEALTH` base value, so a snapshot taken at full health survives an arena with a lower configured maximum.
16. `ArenaManager.join` snapshots before clearing, and calls `leave(player, true)` when the player is already in a *different* arena, so the first inventory is restored before the second snapshot is taken.
17. The two `PlayerInteractEvent` listeners never cancel the same event: `SelectionWandListener` runs at `LOWEST` and `KingPlateListener` at `HIGH`, and `KingPlateListener` calls no `setCancelled` at all.
18. `ArenaCombatListener` registers a handler for both `EntityDamageByEntityEvent` (at `HIGH`) and its supertype `EntityDamageEvent` (at `MONITOR`) in the same class.
19. `config`, `glicko` and `text` import nothing from the plugin — the three leaves. `item` imports only `text`.
20. `me.obvgreen.placeholder` depends on `me.obvgreen.dialog` for `PlaceholderCache`, which places the async leaderboard cache in the dialog package rather than in `database`.
